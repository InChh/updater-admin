# Directory Structure

> How frontend code is organized in this project.

## Overview

The application is a single TanStack Start package. Ordinary authenticated leaf
routes stay thin, while production UI and client behavior are grouped into
domain slices under `src/features/`. Root, authenticated-layout, and login
routes are deliberate composition boundaries described below. Reusable visual
primitives live in `src/components/ui/`; cross-feature browser infrastructure
lives in `src/lib/`; wire contracts shared with the server live in
`src/shared/`.

## Directory Layout

```text
src/
├── build/                # Pure helpers consumed by build configuration
├── components/ui/        # Reusable Solid/Kobalte UI primitives
├── features/<domain>/    # Domain pages, components, API adapters, queries, tests
├── integrations/         # Application-owned framework/provider composition
├── lib/                  # Cross-feature clients, query keys, i18n, Sentry
├── routes/               # Thin page routes and same-origin API transport adapters
├── server/               # Server-only Elysia, auth, domain, DB, and provider code
├── shared/               # Browser/server DTOs, constants, validation utilities
├── test/                 # Shared Vitest setup and repository smoke tests
├── types/                # Narrow ambient declarations for untyped dependencies
├── routeTree.gen.ts      # Generated by TanStack Router; never edit manually
└── styles.css            # Tailwind theme tokens and truly global styles

tests/e2e/                # Playwright full-stack browser journeys
```

## Ownership Rules

### Routes are adapters

Ordinary leaf route files declare `createFileRoute`, validate params/search,
run guards or lightweight prefetches, and connect typed router accessors to a
feature page. They do not own business mutations or large component trees.

Examples:

- `src/routes/_authenticated/programs.index.tsx` adapts typed search and
  navigation to `ProgramsPage`.
- `src/routes/_authenticated/programs.$programId.versions.tsx` parses the UUID,
  prefetches program detail, and renders `VersionsPage`.
- `src/routes/_authenticated/monitoring.audit.tsx` wires validated audit search
  state to the monitoring feature.

The route-level composition exceptions are explicit:

- `src/routes/__root.tsx` owns the document shell, root providers, route error
  capture, and global toast region.
- `src/routes/_authenticated.tsx` owns the protected navigation guard and
  authenticated shell composition.
- `src/routes/login.tsx` owns the unauthenticated sign-in/forced-password
  orchestration and page composition, while delegating field forms, auth-flow
  helpers, the Better Auth browser adapter, and session caching to
  `src/features/auth/` and `src/lib/`.

Do not treat the substantial login composition route as evidence that ordinary
business leaf routes should absorb their feature page trees.

The programs surface has an intentional nested-route split:
`src/routes/_authenticated/programs.tsx` is the `<Outlet />` layout and carries
the `ssr: false` boundary for both children, while
`src/routes/_authenticated/programs.index.tsx` is only the program-list leaf.
Do not collapse the leaf back into the layout; doing so hides or stacks the
`$programId/versions` child.

### Feature slices own domain UI

Each domain keeps the pages, tables/forms/dialogs, client API adapters, query
option factories, search normalization, cache helpers, and colocated unit tests
that it owns together. Not every slice needs every file category. Add to an
existing slice before creating another top-level category.

Examples:

- `src/features/programs/programs-page.tsx`,
  `src/features/programs/queries.ts`, `src/features/programs/search.ts`, and
  `src/features/programs/cache.ts` form the programs slice.
- `src/features/administrators/administrators-page.tsx`,
  `src/features/administrators/api.ts`, and
  `src/features/administrators/administrator-dialogs.tsx` form the
  administrators slice.
- `src/features/versions/version-form.tsx`,
  `src/features/versions/upload-store.ts`, and
  `src/features/versions/upload-workflow.client.ts` keep the complex release
  workflow within the versions slice.

### Shared UI is behaviorally generic

Put primitives in `src/components/ui/` only when their API is independent of a
business domain. Feature-specific composition stays with the feature.

Examples:

- `src/components/ui/button.tsx`, `src/components/ui/dialog.tsx`, and
  `src/components/ui/field.tsx` wrap native or
  Kobalte controls with the project theme and accessibility behavior.
- `src/components/ui/pagination.tsx` and `src/components/ui/table-shell.tsx`
  provide generic list layout; `src/features/programs/program-table.tsx` owns
  program columns.
- `src/components/ui/toast.tsx` is shared feedback infrastructure; program and
  version notification text remains in their feature components/catalogs.

### Cross-layer contracts and infrastructure have separate homes

- Put camelCase DTOs, bounded literal sets, pagination shapes, and cross-layer
  constants in `src/shared/api/`; see `src/shared/api/common.ts`,
  `src/shared/api/programs.ts`, and `src/shared/api/versions.ts`.
- Put browser-facing transport and cache infrastructure in `src/lib/`; see
  `src/lib/api/client.ts`, `src/lib/api/query-keys.ts`, and
  `src/lib/i18n/i18n.tsx`.
- `src/lib/auth-client.ts` is the deliberate Better Auth transport exception to
  the Elysia-oriented `src/lib/api/client.ts`. It owns exactly the three
  browser credential/session POST operations used by the UI and maps bounded
  provider failures into application error codes; feature components do not
  scatter raw Better Auth requests.
- `src/lib/session-query.ts` is an isomorphic `createServerFn` owner. Its
  handler reads the Start request and calls `getSafeSession` on the server,
  while its exported Query options remain safe for route and browser
  consumers. This compiler-managed server-function boundary is a narrow
  exception to the neutral-filename rule, not permission for UI modules to
  import arbitrary server implementation.
- Keep application-level framework/provider composition in `src/integrations/`.
  `src/integrations/tanstack-query/provider.tsx` creates the production query
  client, reports rejected mutations through the browser Sentry boundary, and
  is consumed by `src/router.tsx`; its behavior is covered by
  `src/integrations/tanstack-query/provider.test.ts`.
- Keep build-configuration helpers pure and outside runtime feature code.
  `src/build/sentry-environment.ts` is imported by `vite.config.ts` and tested
  by `src/lib/sentry-build.test.ts`; it is not a browser or server-runtime
  state owner.
- Keep ambient declarations minimal. `src/types/ali-oss.d.ts` deliberately
  declares the untyped package value as `unknown`; the tested browser and
  server adapters narrow their own SDK boundary instead of publishing provider
  types to application code.
- Keep server-only implementation under `src/server/`. Modules outside that
  directory which expose a standalone server boundary use `.server.ts`;
  client-only implementation modules use `.client.ts`/`.client.tsx`. Examples
  are `src/lib/api/default-fetch.server.ts`,
  `src/features/versions/oss-uploader.client.ts`, and the dialog
  implementation `src/features/versions/version-dialogs.client.tsx`. The
  isomorphic `src/features/versions/version-dialogs.tsx` entry point is the
  deliberate neutral-name exception: it uses `createClientOnlyFn`, `lazy`, and
  `ClientOnly` to load that `.client` implementation only after hydration.
  Browser-facing helpers below the dialog boundary, such as
  `src/features/versions/folder-picker.tsx`,
  `src/features/versions/hash-worker.ts`, and
  `src/features/versions/upload-store.ts`, retain precise neutral names. Pure
  helpers already contained by `src/server/`, such as
  `src/server/api/problem.ts`, do not need a second `.server` marker.

## Naming and Test Placement

- Use kebab-case for feature, component, library, and shared filenames:
  `src/features/programs/program-table.tsx`,
  `src/features/settings/system-defaults.ts`, and
  `src/features/shell/navigation-pending.tsx`.
  Files under `src/routes/` instead follow TanStack Router's dots, `$` params,
  and underscore layout conventions; examples are
  `src/routes/_authenticated/monitoring.audit.tsx`,
  `src/routes/_authenticated/programs.$programId.versions.tsx`, and
  `src/routes/_authenticated.tsx`.
- Use PascalCase for exported components and props interfaces, and camelCase
  for functions/controllers/query factories.
- Name standalone environment-specific implementations with `.client` or
  `.server`. An isomorphic neutral entry point is valid when it establishes an
  explicit `createClientOnlyFn`/`ClientOnly` boundary, as
  `src/features/versions/version-dialogs.tsx` does. A neutral client-specific
  leaf helper remains valid only when it is confined behind that boundary.
- Colocate tests as `*.test.ts` or `*.test.tsx`: examples are
  `src/components/ui/pagination.test.tsx`,
  `src/features/programs/programs-page.test.tsx`, and
  `src/features/shell/ui-store.test.ts`.
- Put real browser journeys under `tests/e2e/`: examples are
  `tests/e2e/responsive-accessibility.spec.ts`,
  `tests/e2e/program-management.spec.ts`, and
  `tests/e2e/version-incremental-upload.spec.ts`.
- Existing source imports are relative even though `~/*` is configured in
  `tsconfig.json`; match the surrounding relative-import convention.

## Product Route Surface

The registered product pages are login, programs, nested program versions,
administrators, monitoring overview/audit, profile/account settings, and system
settings. `/` and login without a valid protected `returnTo` resolve to
`/programs`. `src/features/shell/route-registry.ts`, `src/routes/index.tsx`, and
`src/routes/login.tsx` are the current owners. There is no Dashboard, Billing,
tenant, legacy-data migration, or legacy updater-client UI surface; preserve
that approved boundary from `AGENTS.md` rather than inventing unowned routes.

## Avoided and Forbidden Layouts

- Do not edit `src/routeTree.gen.ts`; run `pnpm generate-routes` after route
  changes.
- Do not move feature mutations, query ownership, or large page trees into
  `src/routes/`. Routes are transport/navigation adapters.
- Do not duplicate shared DTOs or concurrency constants inside components;
  import them from `src/shared/api/` and `src/lib/api/`.
- Do not place program/version-specific controls in `src/components/ui/` merely
  to shorten imports.
- Do not runtime-import server-only database, auth, or secret modules into
  feature components or ordinary isomorphic route loaders. A type-only import,
  such as `SafeSessionView` in `src/routes/_authenticated.tsx`, is erased and
  does not cross the runtime bundle boundary. The existing
  `src/lib/session-query.ts` runtime import is valid only because it is owned by
  a `createServerFn` handler and is removed from the browser implementation by
  the TanStack Start transform.
- Do not create generic `utils.ts`, `types.ts`, or `hooks.ts` dumping grounds in
  a feature when a precise file such as `search.ts`, `queries.ts`, or `cache.ts`
  expresses the owner.
